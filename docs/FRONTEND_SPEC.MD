## 1. ОБЩИЕ ПРИНЦИПЫ

### 1.1. Технологии

| Компонент | Технология | Причина |

| Роль | Доступные страницы |
|------|-------------------|

**Общие фильтры (верхняя панель):**
- **Склад** — выпадающий список с поиском. Пустое значение = все склады. Уходит в запросы KPI, плашек остатков и графиков как `warehouse_code`.
- **Подразделение** — выпадающий список с поиском по названию, рядом со складом. Пустое значение = «Все подразделения». Источник: `GET /references/departments?has_normatives=true` — только подразделения, у которых есть или когда-либо были нормативы (`normatives → clients.department_id`, включая истёкшие и удалённые строки). Смена подразделения обновляет плашки остатков, KPI и графики тем же способом, что и смена склада: параметр `department_id` уходит в `GET /dashboard/summary`, `normative-trend`, `exceptions`, `warehouse-coverage`, `expiry-calendar`, `nz-by-department`, `top-clients`.

**Остатки компании (`CompanyStockRow`, тот же `GET /dashboard/summary`):**

Две карточки над KPI, всегда в тоннах, три знака после запятой, разделитель тысяч. Переключатель `т|кг` и фильтр клиента у графика на них не влияют.

Плашки **пересчитываются** при смене склада, подразделения и дат «От»/«До» у графика динамики (эти даты уходят в `GET /dashboard/summary` как `date_from` / `date_to`). Гранулярность «День / Неделя / Месяц», артикул и клиент плашки не режут. Без склада, подразделения и дат — сумма по всем текущим строкам `available_balances`.

| Карточка | Поле | Логика |
|----------|------|--------|
| Фактический остаток | `total_full_stock` | Сумма `full_stock` |
| Доступный остаток | `total_available` | Сумма `available` |

**Склад.** Без подразделения — все артикулы выбранного склада. С подразделением — пересечение: только пары склад + артикул из действующих НЗ этого подразделения.

**Подразделение.** Только пары склад + артикул из действующих НЗ клиентов этого подразделения. Если таких НЗ нет — оба значения 0.

**Даты «От»/«До».** Без дат — текущие `available_balances`. Если задана хотя бы одна граница — последний снимок каждой пары склад + артикул в диапазоне из `available_balances_history` (`snapshot_date`). Нет снимка в диапазоне — позиция в сумму не входит. Даты стоят в шапке графика динамики, но те же значения уходят в `summary` для плашек.

Строка в килограммах делится на 1000, тонны остаются тоннами, штуки умножаются на `products.weight_kg` и делятся на 1000. Отрицательные величины входят в сумму. Итог округляется до 3 знаков.

**KPI-панель (`NorthStarRow`, 5 карточек, `GET /dashboard/summary`):**

| Карточка | Формат | Логика |
|----------|--------|--------|
| Активных НЗ | масса, 3 знака | Сумма действующих нормативов в выбранной единице (`т` / `кг`) |
| Дефицит | масса, 3 знака | Сумма дефицитов с учётом перемещений: по позициям НЗ `max(0, норматив − запланировано)` |
| Покрытие с учётом перемещений | % | `(общий НЗ − сумма этих дефицитов) / общий НЗ × 100` |
| Покрытие доступным стоком | % | Та же формула, но дефицит позиции = `max(0, норматив − доступно)`, без плана |
| Истекают 30д | масса, 3 знака | Сумма нормативов с `expiry_date` в ближайшие 30 дней |

Позиция — пара склад + артикул среди действующих НЗ. Если общий НЗ равен нулю, оба покрытия равны 0%. Если по всем позициям дефицит неположительный, покрытие этой формулы равно 100%. Тонны и килограммы в ответе округляются до 3 знаков; на карточках масса показывается с тремя знаками после запятой.

**Графики:**

«Изменение нормативов во времени» (`NormativeTrendChart`, `GET /dashboard/normative-trend`):
- Артикул — автокомплит по всему справочнику `GET /references/products?search=`. В списке `код — название`. Поиск не ограничен заранее загруженной страницей.
- Клиент — необязательный автокомплит `GET /references/clients?q=`. Выбранный `client_id` фильтрует этот график и «Текущее покрытие по складам».
- Период day/week/month, опционально от/до, горизонтальный скролл. Без склада серии по складам; при складе без артикула — топ-9 артикулов и «Остальные».

«НЗ в разрезе управлений продаж» (`NzByDepartmentChart`, `GET /dashboard/nz-by-department`):
- Горизонтальные бары: подпись подразделения на оси целиком, без обрезки.
- Реагирует на общие фильтры «Подразделение» и «Склад» (`department_id`, `warehouse_code`).
- Stacked bar по складам. Цвет склада — тот же ранг, что на графике нормативов (`warehouseTrendColors`: топ-3 яркие, остальные бледные).

«Топ-10 клиентов по объёму НЗ» (`TopClientsChart`, `GET /dashboard/top-clients`):
- Реагирует на общие фильтры «Подразделение» и «Склад».
- Десять клиентов по убыванию объёма и, если за ними есть объём, одиннадцатый бар «Остальные».
- «Остальные» серые (`#9CA3AF`) и всегда последние, даже если их сумма больше любого клиента из топа.

**Компоненты:**
- `CompanyStockRow` — две плитки `total_full_stock` и `total_available` из `GET /dashboard/summary`; всегда тонны, три знака; реагируют на склад, подразделение и «От»/«До»
- `NorthStarRow` — пять плиток `GET /dashboard/summary`; массы в `т`/`кг` с тремя знаками
- `NormativeTrendChart` — stacked bar `GET /dashboard/normative-trend`
- `WarehouseCoverageChart` — `GET /dashboard/warehouse-coverage` (стек доступно / запланировано / дефицит и норматив рядом). Без фильтра подразделения и клиента в стек входят все остатки склада. С фильтром — только артикулы из НЗ этого подразделения или клиента. Покрытие такого отбора: `(норматив − сумма дефицитов) / норматив`, 100% если все позиции покрыты.
- `ExceptionsTable` — `GET /dashboard/exceptions` (дефицит > 0, топ-20)
- `ExpiryHeatmap` — `GET /dashboard/expiry-calendar`

**Drill-down:**
- клик по столбцу графика → фильтр по дате и таблица деталей периода;
- клик по строке исключения → карточка запроса (`request_id`) или дашборд логиста.

### 3.2.1. Аналитика запасов

**URL:** `/analytics`

**Назначение:** динамика нормативного запаса, доступного остатка и фактической реализации одного продукта (LOG-054).

**Доступ:** все авторизованные роли, включая `admin` и `guest`. Пункт меню «Аналитика».

Над страницей вкладки «По артикулу» (`/analytics`) и «По клиенту» (`/analytics/client`). Сайдбар для обоих адресов подсвечивает «Аналитика».

**Макет (текстовый):**
┌─────────────────────────────────────────────────────────────────────────────┐
│  Аналитика запасов                                                         │
├─────────────────────────────────────────────────────────────────────────────┤
│  Продукт: [автокомплит]     Подразделение: [▼]                            │
│  Период: [01.08.2026 — 27.10.2026]   Гранулярность: [Месяц ▼]             │
│  [ ] Показывать фактические остатки                                        │
├─────────────────────────────────────────────────────────────────────────────┤
│  Столбцы: Норматив (синий; неделя /4, день /28)                          │
│  Месяц: пунктир мин/макс и сплошная медиана                            │
│  Неделя: только пунктир мин/макс. День: сплошная линия запаса дня      │

├─────────────────────────────────────────────────────────────────────────────┤
│  Сводка 6 месяцев (медиана, реализация, средний норматив)                  │
└─────────────────────────────────────────────────────────────────────────────┘

**Фильтры верхней панели:**

| Фильтр | Обязательный | Источник |
|--------|--------------|----------|
| Продукт | да, один | `ProductAutocomplete`, `GET /references/products?search=` |
| Подразделение | нет, один | `GET /references/departments?has_normatives=true` (`clients.department_id`) |
| Период | да | Range picker |
| Гранулярность | да | День / Неделя / Месяц |
| Показывать фактические остатки | нет | Галочка на странице, по умолчанию выключена |

Отдельных фильтров «Клиент» и «Склад» в верхней панели нет. Их заменяют таблицы под графиком.

Без продукта график не строится, на месте графика текст «Выберите продукт».

**Период по умолчанию** (график открывается в месяцах). Смена гранулярности **всегда** ставит период заново по таблице ниже, даже если пользователь уже двигал даты. Смена продукта, подразделения и галочек клиентов/складов даты не сбрасывает.

| Грануляция | Период по умолчанию |
|------------|---------------------|
| День | Последние 90 календарных дней, включая сегодня |
| Неделя | Последний год |
| Месяц | Последние 12 месяцев (`today − 12 months` … сегодня) |

Гранулярность по умолчанию — **месяц**. Эндпоинт `GET /analytics/stock-dynamics/bounds` страница больше не вызывает: «всё время» для месяца не используется.

**График** (`StockDynamicsChart`, `GET /analytics/stock-dynamics`):

- Recharts `ComposedChart`.
- Норматив — синие столбцы `#1677ff`. На месяце это уровень запаса. На неделе тот же уровень делится на 4, на дне — на 28.
- Остаток не бывает отрицательным: минусовый снимок заменяется нулём. На месяце пунктир — минимум (`#95de64`) и максимум (`#237804`) дневных остатков, сплошная зелёная `#52c41a` — медиана. На неделе только минимум и максимум, без медианы. На дне остаётся только сплошная линия «Доступный запас» — сумма складов за этот день. Минимум и максимум считаются только по дням, где есть слепок; день без слепка не становится нулём.
- Реализация — оранжевая линия `#fa8c16`, сумма отгрузок за месяц, неделю или день. Накопления нет.
- Фактический остаток — пунктирные линии `full_stock_min`, `full_stock_median`, `full_stock_max`. Галочка «Показывать фактические остатки» стоит рядом с гранулярностью и по умолчанию выключена: линии и пункты легенды скрыты. Включённая галочка повторяет правило доступного остатка: на неделе только минимум (`#D1D5DB`) и максимум (`#6B7280`), без медианы; на месяце к ним добавляется медиана (`#9CA3AF`); на дне остаётся итог дня. Пустая серия в легенду не попадает. Состояние галочки живёт на странице и не сбрасывается при смене продукта, подразделения, периода, гранулярности и галочек клиентов и складов.
- Ось Y — тонны, подписи до 3 знаков. Легенда своя: «Норматив», «Мин. остаток», «Медиана остатка» (на дне — «Доступный запас»), «Макс. остаток», при включённой галочке «Мин. фактический остаток», «Медиана факт. остатка» (на дне — «Фактический остаток»), «Макс. фактический остаток», «Реализация». Пустые серии в легенду не попадают.
- Если за период нет ни одного норматива — пустой блок и текст «Нет данных за период». `null` не превращается в ноль и не даёт точку.
- Если сняты все клиенты и все склады — график не запрашивается, на его месте текст «Выберите хотя бы один склад или клиента». Снятые только клиенты график не прячут: норматив и остаток остаются, реализация пустая.
- Под графиком две таблицы (`ShipmentSelectionTables`, `GET /analytics/filters?product_code=`). Слева клиенты, справа склады. В строке чекбокс, название и сумма отгрузок за 6 календарных месяцев, включая текущий, в килограммах с двумя знаками. В список попадают только те, у кого за это окно была отгрузка выбранного продукта. Сортировка по сумме по убыванию. Длинный список прокручивается внутри таблицы. Над таблицами счётчик «Выбрано: X из Y клиентов, Z из W складов». По умолчанию включены все строки. Смена продукта заново включает все галочки.
- Снятый клиент не входит в серию «Реализация». Норматив и остатки от галочки клиента не зависят. Снятый склад не входит в норматив, доступный остаток и фактический остаток. Отгрузки с его пункта отгрузки тоже не входят в реализацию, даже если клиент включён. Пока все галочки включены, `client_ids` и `warehouse_codes` не передаются: график считает всех, как раньше. Снятая галочка передаёт оставшиеся id.
- Под таблицами сводка «Сводка за последние 6 месяцев» (`GET /analytics/stock-summary`): месяц, медианный остаток, реализация и средний дневной норматив. Шесть календарных месяцев, включая текущий. Пересчитывается при смене продукта, подразделения и галочек. Пустая ячейка — «—». Внизу строка «Среднее»: среднее по месяцам, где в колонке есть число. Пустой месяц в среднее не входит. При полностью снятом выборе сводка скрыта.

### 3.2.2. Аналитика по клиенту

**URL:** `/analytics/client`, карточка `/analytics/client/:clientId`

**Назначение:** норматив и фактические отгрузки одного клиента (LOG-071). Остатки склада и пополнения на страницу не выходят.

**Доступ:** все авторизованные роли, включая `admin` и `guest`. Вкладка «По клиенту» на «Аналитике». Ссылка «Аналитика» в каждой строке `/references/clients`, включая служебного клиента и роль `guest`.

**Макет (текстовый):**

```
Аналитика
[ По артикулу ]  [ По клиенту ]

Клиент: [автокомплит]     Период: […]     Грануляция: [Месяц ▾]
[x] Учитывать родственные артикулы в покрытии

Срез отмеченных складов и артикулов
Норматив сейчас · Среднемесячная · Покрытие · Реализация за период

Столбцы: Норматив (уровень; неделя /4, день /28)
Линия: Реализация за бакет

Выбрано складов: X из Y          Выбрано артикулов: Z из W
Склады (чекбокс, норматив, среднемесячная, за период, покрытие)
Пункты отгрузки без склада
Артикулы (те же колонки)
```

**Фильтры:**

| Фильтр | Обязательный | Поведение |
|--------|--------------|-----------|
| Клиент | да, один | `ClientAutocomplete`. Выбор пишет адрес `/analytics/client/:id`. Сброс — `/analytics/client` |
| Период | да | Range picker. Те же периоды по умолчанию, что у `/analytics` |
| Грануляция | да | День / неделя / месяц. Смена заново ставит период |
| Родственные артикулы | нет | Галочка, по умолчанию включена. Не сбрасывается при смене клиента |

Подразделение фильтром не является: под полем клиента показывается `department_name` из ответа. У служебного клиента — пояснение, что здесь собраны нормативы до справочника клиентов.

Без клиента график и таблицы скрыты, текст «Выберите клиента». Смена клиента сбрасывает галочки складов и артикулов в «все включены», грануляцию в месяц и период в последние 12 месяцев.

**График** (`ClientConsumptionChart`, `GET /analytics/clients/{id}`):

- Только норматив и реализация. Доступный и фактический остаток не запрашиваются.
- Норматив — исторический уровень: сумма строк клиента, чьё окно пересекает бакет. Месяц — уровень в тоннах. Неделя — уровень / 4, день — уровень / 28.
- Реализация — сумма `actual_shipments` этого клиента за бакет, без накопления. Пустой бакет — `null`, не ноль.
- В обе серии входят только отмеченные склады и отмеченные артикулы. Родственники линию не расширяют.
- Пока отмечены все склады, параметр складов не передаётся: в линию входят и пункты отгрузки без склада. Сужение складов эти пункты из графика убирает.
- Нет ни одной точки — «Нет данных за период». Сняты все склады или все артикулы — график и плашка среза заменяются текстом «Отметьте хотя бы один склад и один артикул». Запрос при этом уходит с пустым списком, таблицы остаются.
- Нет ни склада, ни артикула, ни пункта без склада — «По клиенту нет нормативов и реализации за период».

**Срез** над графиком считает пересечение отмеченных складов и артикулов:

- норматив сейчас — действующие строки клиента, без родственников;
- среднемесячная — окно согласования экономиста (6 полных предыдущих месяцев). При включённой галочке в делитель добавляются отгрузки родственников отмеченных артикулов, каждый код один раз. Если отмечены все артикулы, галочка итог не меняет: родственник и так в полном списке;
- покрытие — норматив / среднемесячная, один знак. Нет месяца с отгрузкой ≥ 1 кг — «нет реализации»;
- реализация за период — сумма отгрузок отмеченного среза за даты графика. Пусто — «—».

Если в срезе норматив нулевой, а среднемесячная или реализация за период есть, под цифрами строка «В срезе есть потребление, которого нет в нормативе клиента».

**Таблицы.** Галочки фильтруют только график и срез. Цифра в строке — весь склад или весь артикул клиента, чужая галочка её не меняет. По умолчанию включены все. Шапка таблицы снимает и возвращает все строки. Счётчик «Выбрано складов: X из Y» и «Выбрано артикулов: Z из W».

Колонки обеих таблиц: норматив сейчас, среднемесячная, за период, покрытие. Единица — тонны. Пустая реализация — «—». Покрытие красится границами `GET /params`: до `coverage_high_months` включительно зелёным, до `coverage_low_months` включительно обычным текстом, выше и при «нет реализации» — красным. Если параметры не загрузились, границы 2 и 4.

Строка попадает в таблицу, если у клиента по этому складу или артикулу есть норматив, действующий сегодня или пересекающий период графика, либо отгрузка в окне среднемесячной или в периоде графика.

Порядок строк по умолчанию, без клика по заголовку: сначала `outside_normative` (потребление при нулевом нормативе), затем норматив без реализации, по убыванию норматива, затем покрытие по убыванию. Внутри равенства — название. Такая строка залита `#fff7e6` и помечена «Нет в нормативе».

Среднемесячная артикула считается только по отгрузкам, сопоставленным с активным складом. Колонка «За период» у артикула включает и несопоставленные пункты. Если у артикула есть родственник с собственной среднемесячной больше нуля, ячейка залита `#fff1b8`, подсказка перечисляет код, название и среднемесячную родственника. Галочка добавляет эти отгрузки в число ячейки и в покрытие. Норматив строки остаётся только своим.

Строка склада суммирует все артикулы клиента на этом складе. Галочка родственников её не меняет: отгрузка родственника с этого склада уже входит в сумму.

Под таблицей складов, если есть пункты отгрузки без активного склада, отдельная таблица без чекбоксов: пункт, среднемесячная, за период, покрытие. Те же строки залиты `#fff7e6`. В покрытие артикула они не входят. В график и срез попадают, только пока отмечены все склады.

Экспорта в Excel нет.

**Компоненты:**
- Переключатель типа запроса (нормативный / разовый). У `logistics`/`admin` выключен, тип всегда «Разовое перемещение»
- Поле "Клиент" (автокомплит из истории)
- Подразделение инициатора подставляется автоматически из профиля пользователя (на форме не редактируется)
- Поле "Срок действия" (только для нормативных): календарь предзаполнен датой создания + 3 месяца (минимум). Коммерсант может увеличить срок вручную в пределах от `CURRENT_DATE + 3 months` до `CURRENT_DATE + 6 months`. Подсказка под полем: «По умолчанию срок 3 месяца — минимальный для актуальности нормативов»
- Таблица позиций:
  - Над таблицей — Alert (info), только если в параметрах включён переключатель «запросы кратно паллетной норме»: «В настоящее время запросы на нормативный запас/разовое перемещение принимаются только кратно поддонной норме». Количество при создании округляется вверх до кратного поддону: в штуках — `pallet_qty` шт (или 1 шт); в тоннах — через `weight_kg` (1 т = 1000 кг), вверх до целых поддонов. Согласующие могут изменить количество как угодно.
  - Автокомплит артикула (`ProductAutocomplete` с `include_analogs=true`): основной продукт и активные аналоги с пометкой «Аналог». При выборе аналога в запрос подставляется код аналога
  - Название подставляется из справочника
  - Выпадающий список складов; по складу подставляется удалённость (`objects.long_distance`)
  - **Количество в месяц** (ввод) — заголовок столбца для нормативного запроса. Рядом с заголовком иконка «?» с тултипом: «Необходимо указать месячную реализацию для вашего клиента. Логистика будет автоматически восполнять норматив до заданного уровня по мере реализации». Для разового перемещения столбец остаётся «Кол-во» без этого тултипа
  - Единица измерения: по умолчанию `т` для нормативного запроса и разового перемещения, в том числе для строк, которые создаёт «Рассчитать оптимальный запас». `шт` записывается только после переключения указателя в строке.
  - Информационные поля (не редактируются; отображаются только для нормативных запасов, для разовых перемещений отключены):
    - **Категория** — из справочника продукта, с коэффициентом: `A (×1.0)`, `B (×1.5)`, `C (×2.0)`
    - **Удалённость** — из склада: `Нет (×1.0)` / `Да (×1.5)`
    - **Потребность** = Количество × коэффициент категории × коэффициент удалённости, округление до 32 знаков
  - Тултип на «Потребность»: `Расчёт: 1000 шт × 1.5 (категория B) × 1.5 (удалённый склад) = 2 250 шт`
  - Для разовых перемещений (`request_type = one_time`) столбцы «Категория», «Удалённость» и «Потребность» скрыты, так как расчёт потребности с учётом коэффициентов не применяется.
- Кнопка "Добавить позицию"
- Кнопка «Рассчитать оптимальный запас» (🪄) — только для нормативного запроса, над таблицей позиций. Активна сразу, без заполненных строк. Без выбранного клиента нажатие просит выбрать клиента. Вызывает `POST /requests/calculate-optimal` только с `client_id`: сервер находит все отгрузки клиента по всем складам и артикулам.
- Модалка расчёта:
  - клиент;
  - предупреждение, если среди уже введённых строк есть те же артикул и склад: «Количество в уже добавленных строках будет перезаписано»;
  - таблица позиций: артикул, название, склад, количество кг/мес, число месяцев, статус (✅ или ⚠️ с причиной);
  - действующие коммерческие нормативы со ссылкой «открыть» на `/requests/{id}` в новой вкладке.
  - «Применить» создаёт строки запроса в тоннах по всем прошедшим расчёт позициям. Пустая заготовка строки заменяется этими строками. Совпадающие артикул и склад получают новое количество в единице этой строки: если пользователь оставил тонны, килограммы делятся на 1000; если переключил на штуки — делятся на `weight_kg`. Остальные уже введённые строки остаются. Если включено округление до поддона, количество затем округляется вверх. Пропущенные расчётом строки не добавляются. «Применить» не решает, завершать ли прежние запросы. «Отмена» форму не меняет.
- Кнопки: "Отмена", "Сохранить черновик", "Отправить"
- «Сохранить черновик» не записывает `auto_complete_previous`.
- «Отправить» для нормативного запроса вызывает `POST /requests/overlapping-normatives` по позициям, которые уходят в запрос. Если найдены действующие коммерческие запросы, окно показывает их ссылками в новой вкладке и одну галочку, по умолчанию включённую. Под галочкой виден один текст: при включении — завершение всего найденного запроса в день утверждения экономистом, при снятии — увеличение без отмены прежнего норматива. Выбор уходит в `POST /requests/{id}/submit`. Та же проверка стоит на карточке черновика у «Отправить на согласование».
- На карточке запроса и в окне согласования ПП и экономиста пометка, не переключатель. При флаге: «Коммерсант завершает действующие запросы в день утверждения» и ссылки. Без флага, если по позициям есть действующие нормативы: «Увеличение по действующей позиции, прежний норматив сохраняется. Количество прибавится к текущему» и те же ссылки.

**URL:** `/requests/{id}`

При прокрутке страницы обе строки шапки остаются у верхнего края окна, пока видны строки этого склада; у следующего раскрытого склада прилипает уже его шапка. Таблица занимает ширину панели склада.

Родственные артикулы переставляются одним блоком: Норматив, Потребность и Дефицит сравниваются по главному артикулу, Доступно, четыре колонки перемещений и Доступно + Запланировано — по сумме группы. Внутри блока главный остаётся первым.

   Переключатель шт/т пересчитывает Норматив, Потребность, Доступно, четыре колонки перемещений, Доступно + Запланировано и Дефицит. В БД `no_ready`, `ready`, `collected` и `on_way` хранятся в кг. На экране они пересчитываются так же, как «Доступно» и «Доступно + Запланировано»: `шт` = кг / `weight_kg`, `т` = кг / 1000. Округление как у «Доступно»: до 2 знаков в штуках и до 6 знаков в тоннах. `null` и 0 показываются как 0, без прочерка.

   Колонка **Доступно** — `available`. **Перемещения: не произведено** — `no_ready`. **Перемещения: произведено** — `ready`. **Перемещения: собрано в ТС** — `collected`. **Перемещения: в пути** — `on_way`. **Доступно + Запланировано** — `plan` (сумма этих пяти полей). Колонка **Категория** (A/B/C) показывает, какой коэффициент применён к потребности. Колонка **Потребность** = Норматив × коэффициент категории × коэффициент удалённости; подсказка на значении поясняет множители.

4.0. **Группировка родственных артикулов (LOG-006)** — строки одного склада, связанные цепочкой `parent_code` / `children_code`, стоят подряд. Группы визуально разделены **только чередованием фона** (светло-серый / белый) и тонкой верхней границей. Заголовков «ГРУППА» нет.

Правила группы:

- **Главный артикул** — `is_active = true` и `children_code IS NULL`. Стоит **первым**.
- **Остальные** — любые связанные через parent/children (активные и неактивные); у них обычно заполнен `children_code` (предшественники главного).
- У главного: **Норматив** и **Потребность** — сумма по группе; **Доступно**, четыре колонки перемещений и **Доступно + Запланировано** — только свои; **Дефицит** = потребность группы − сумма «Доступно + Запланировано» всех членов группы.
- У остальных: те же колонки, но Норматив, Потребность и Дефицит скрыты (общее для группы). Доступно, четыре колонки перемещений и Доступно + Запланировано — свои, чтобы был виден остаток по старому артикулу. Ноль в колонках перемещений показывается как 0.
- В разнарядке (`generate-orders` / B2B) позиция создаётся **на главный артикул** с групповым дефицитом. Устаревший код не заказывается.

Пример (10001 — старый, 10004 — главный):

│ 10004    │ Подшипник (нов.) │ A  │ 1 000   │ 1 000      │ 100      │ 0              │ 0          │ 0            │ 0       │ 100                      │ 🔴 300  │
│ 10001    │ Подшипник (стар.)│ A  │ —       │ —          │ 600      │ 0              │ 0          │ 0            │ 0       │ 600                      │ —       │

Дефицит группы = 1000 − (100 + 600) = 300, заказ на 10004.

4.1. **Информационное сообщение для удалённых складов** — если у склада `long_distance = true`, над таблицей позиций показывается Alert:

«Ввиду удалённого расположения склада, пополнение возможно по железной дороге — срок доставки около 1 месяца от даты готовности продукции на производственной площадке, в связи с чем нормативы увеличены»

- Кнопка «Создать»

**Модалка «Редактировать объект»:**

8. ПЕРЕСЧЕТ ЕДИНИЦ (шт ↔ т)
Формула:

text
1 т = 1000 кг
Вес единицы = products.weight_kg (кг)
Количество в тоннах = (Количество в штуках × weight_kg) / 1000, отображение до 6 знаков после запятой
Колонки перемещений на дашборде логиста приходят из кг: шт = кг / weight_kg, т = кг / 1000. Ноль показывается как 0. В штуках округление до 2 знаков, как у «Доступно»
Пример:

text
Подшипник 6204ZZ: weight_kg = 0.25 кг
1000 шт = (1000 × 0.25) / 1000 = 0.25 т
