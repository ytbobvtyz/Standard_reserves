## 1. ОБЩИЕ ПРИНЦИПЫ

### 1.1. Технологии

| Компонент | Технология | Причина |
|-----------|------------|---------|
| **Фреймворк** | React 18+ | Универсальность, экосистема |
| **Сборка** | Vite | Быстрая разработка, горячая перезагрузка |
| **Стейт-менеджмент** | Zustand | Лёгкий store для auth; остальное — локальный `useState` |
| **Роутинг** | React Router v6 | Навигация по страницам |
| **UI-библиотека** | Ant Design | Таблицы, формы, модалки |
| **HTTP-клиент** | Axios | Bearer-токен, обработка 401 |
| **Типизация** | TypeScript | Безопасность, авто-дополнение |

### 1.2. Роли и страницы

| Роль | Доступные страницы |
|------|-------------------|
| **Все (авторизованные)** | Вход, профиль |
| **Guest (наблюдатель)** | Дашборд (только чтение), Нормативы без вкладки партий, Справочники |
| **Commercial** | Мои запросы, Создать запрос, Карточка запроса, Нормативы без вкладки партий |
| **PP** | Согласование (ПП), Все запросы, Карточка запроса, Нормативы (вкладка «Партии загрузки») |
| **Economist** | Согласование (экономист), Все запросы, Карточка запроса, Нормативы (вкладка «Партии загрузки») |
| **Logistics** | Дашборд логиста (нормативы + разовые), Управление остатками, Администрирование пользователей и подразделений, Нормативы (вкладка «Партии загрузки») |

### 3.4. Создать запрос (Create Request)

**URL:** `/requests/create`

**Назначение:** Создание нового запроса (нормативного или разового).

**Макет (текстовый):**
┌─────────────────────────────────────────────────────────────────────┐
│ 📝 Создать запрос │
├─────────────────────────────────────────────────────────────────────┤
│ │
│ Тип запроса: ○ Нормативный ● Разовое перемещение │
│ │
│ Клиент: [] │
│ │
│ Срок действия: [2026-12-31 📅] (только для нормативных) │
│ │
│ ──── Позиции ──────────────────────────────────────────────────── │
│ │
│ Артикул │ Название │ Склад │ Кол-во │ Ед │ Категория │ Удалённость │ Потребность │
│ [10001 ▼] │ Подшипник 6204ZZ│ [Ростов ▼] │ [1000] │ шт │ A (×1.0) │ Нет (×1.0) │ 1 000 шт │
│ [10002 ▼] │ Корпус чугунный │ [Владик ▼] │ [500] │ шт │ B (×1.5) │ Да (×1.5) │ 1 125 шт │
│ [➕ Добавить позицию] │
│ │
│ Комментарий: [_______________] │
│ │
│ [ Отмена ] [ Сохранить черновик ] [ Отправить ]│
└─────────────────────────────────────────────────────────────────────┘

text

**Компоненты:**
- Переключатель типа запроса (нормативный / разовый)
- Поле "Клиент" (автокомплит из истории)
- Подразделение инициатора подставляется автоматически из профиля пользователя (на форме не редактируется)
- Поле "Срок действия" (только для нормативных): календарь с датой по умолчанию +6 месяцев от текущей; доступны только даты от `CURRENT_DATE + 3 months` до `CURRENT_DATE + 6 months`. Подсказка: «Минимальный срок — 3 месяца, максимальный — 6 месяцев»
- Таблица позиций:
  - Автокомплит артикула (`ProductAutocomplete` с `include_analogs=true`): основной продукт и активные аналоги с пометкой «Аналог». При выборе аналога в запрос подставляется код аналога
  - Название подставляется из справочника
  - Выпадающий список складов; по складу подставляется удалённость (`objects.long_distance`)
  - Количество (ввод)
  - Единица измерения
  - Информационные поля (не редактируются):
    - **Категория** — из справочника продукта, с коэффициентом: `A (×1.0)`, `B (×1.5)`, `C (×2.0)`
    - **Удалённость** — из склада: `Нет (×1.0)` / `Да (×1.5)`
    - **Потребность** = Количество × коэффициент категории × коэффициент удалённости, округление до 32 знаков
  - Тултип на «Потребность»: `Расчёт: 1000 шт × 1.5 (категория B) × 1.5 (удалённый склад) = 2 250 шт`
- Кнопка "Добавить позицию"
- Кнопки: "Отмена", "Сохранить черновик", "Отправить"

**Компоненты:**

1. **Переключатель единиц измерения** (глобальный для дашборда):
   - `шт` — показываем всё в штуках
   - `тонны` — пересчитываем через `weight_kg` (1 т = 1000 кг, делим на вес единицы)

2. **Переключатель фильтрации запасов:**
   - `Все запасы` — показываем все товары на складе
   - `Только с нормативами` — показываем только те товары, на которые есть активный норматив
   - `Требуют пополнения` — показываем только товары с дефицитом (потребность > план)

3. **Группировка по складам** — только те склады, где есть позиции с дефицитом (при фильтре "Требуют пополнения") или все склады с нормативами.

4. **Таблица с двумя строками** — в штуках и тоннах (если выбран режим показа "шт", то тонны показываем как дополнительную информацию; если выбран режим "тонны" — наоборот). Переключатель шт/т пересчитывает Норматив, Потребность, Доступно, Запланировано и Дефицит. Колонка **Категория** (A/B/C) показывает, какой коэффициент применён к потребности. Колонка **Потребность** = Норматив × коэффициент категории × коэффициент удалённости; подсказка на значении поясняет множители. Дефицит = Потребность − Запланировано.

4.1. **Информационное сообщение для удалённых складов** — если у склада `long_distance = true`, над таблицей позиций показывается Alert:

«Ввиду удалённого расположения склада, пополнение возможно по железной дороге — срок доставки около 1 месяца от даты готовности продукции на производственной площадке, в связи с чем нормативы увеличены»

5. **Кнопка «Загрузить актуальные остатки»** (только `logistics`):
   - Открывает модалку с Drag-and-Drop (Excel `.xlsx` / `.xls`)
   - После ответа: отчёт «Загружено X, ошибок Y» и список ошибок по строкам
   - Дашборд обновляется после успешной загрузки

6. **Блок актуальности остатков** (все роли на дашборде):
   - `GET /logistics/normative/sync-info`
   - Дата и время последней загрузки: `ДД.ММ.ГГГГ ЧЧ:ММ`
   - Кто загрузил: фамилия и инициал имени, в скобках роль
   - Пример: `📦 Актуальные остатки обновлены: 22.08.2026 14:30` / `👤 Кто: Иванов И. (logistics)`
   - Если загрузок не было: «Актуальные остатки ещё не загружались»

7. **Кнопки формирования заказов** (только `logistics`):
   - «Сформировать заказы на выбранные склады» / «Сформировать заказы на все склады»
   - После ответа `POST /logistics/normative/generate-orders` открывается модальное окно предпросмотра (см. §3.7.1)

### 3.7.1. Модальное окно формирования заказов (`OrderPreviewModal`)

**Назначение:** предпросмотр заказов, выборочная выгрузка разнарядок B2B, подтверждение формирования.

**Текущее поведение (до LOG-021):** после «Сформировать заказы» открывалась модалка с предпросмотром; кнопки «Подтвердить» и «Скачать Excel».

**Новое поведение:**

- Список маршрутов (завод → склад) с чек-боксами
- По умолчанию выбраны **все** маршруты
- Чек-бокс «Выбрать все маршруты» (включая промежуточное состояние)

- **«Подтвердить»** — как раньше: фиксирует **все** маршруты из предпросмотра (не только отмеченные чек-боксами) и закрывает модалку
- **«Отмена»** — закрывает модалку без подтверждения
- Кнопка «Скачать Excel» в модалке **убрана**; выгрузка Excel дашборда остаётся на странице после подтверждения заказов

4.4. ProductAutocomplete
tsx
<ProductAutocomplete
    value={productCode}
    onChange={setProductCode}
    placeholder="Поиск по артикулу или названию"
    includeAnalogs
/>

При `includeAnalogs` запрос уходит с `include_analogs=true`. В выпадающем списке:
- основной найденный продукт;
- активные аналоги с пометкой «Аналог».

При точном вводе кода неактивного товара он остаётся видимым с пометкой
«Не активен», но его опция заблокирована. Выбрать можно только активный товар
или активный аналог. Выбор аналога подставляет **его** `code` в позицию запроса.

В списке запросов (`RequestCard` / таблица) отображается колонка **Подразделение** (снимок с запроса).

6. СОСТОЯНИЯ (STORES)
6.1. AuthStore (Zustand)

На фронте реализован один store — `src/stores/auth.ts` (Zustand). Списки запросов, согласование, логистика и справочники хранятся в локальном `useState` страниц, без Pinia/RequestStore.

typescript
interface AuthStore {
    user: User | null;
    token: string | null;
    isAuthenticated: boolean;
    login(username: string, password: string): Promise<void>;
    logout(): Promise<void>;
    refreshToken(): Promise<void>;
}

8. ПЕРЕСЧЕТ ЕДИНИЦ (шт ↔ т)
Формула:

text
1 т = 1000 кг
Вес единицы = products.weight_kg (кг)
Количество в тоннах = (Количество в штуках × weight_kg) / 1000
Пример:

text
Подшипник 6204ZZ: weight_kg = 0.25 кг
1000 шт = (1000 × 0.25) / 1000 = 0.25 т
Отображение в таблице (две строки или две колонки):
